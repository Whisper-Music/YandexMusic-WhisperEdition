# Вход по почте: что обязан делать сервер Whisper Archive

Приложение (`src/core/rust/whisper/auth.rs`) ограничивает частоту запросов кода и попыток ввода, но это
только защита от собственного интерфейса: любой может отправить запрос к API напрямую, в обход
приложения. Настоящая защита — на сервере. Серверного кода в этом репозитории нет, поэтому ниже —
требования, которые нужно проверить и выполнить в коде сервера архива.

## `POST /api/auth/request-code`

- **Лимит по адресу почты** (нормализованному: обрезка пробелов, нижний регистр): не чаще 1 письма в 60 с
  и не больше 5 в час. Ответ при превышении — `429` с заголовком `Retry-After`.
- **Лимит по IP** (для IPv6 — по префиксу /64): например, не больше 10 писем в час и 30 в сутки на любые адреса.
- **Общий лимит на сервис** на случай распределённой атаки (сотни IP) — с алертом.
- Ответ **одинаковый** для существующего и несуществующего аккаунта (нельзя проверять, зарегистрирован ли адрес).
- Новый код **отменяет** все прежние коды этого адреса.

## `POST /api/auth/token`

- **Срок действия кода** — 10 минут (не больше 15).
- **Одноразовость**: код помечается использованным в той же транзакции, где выдаётся ключ
  (атомарно — два параллельных запроса с одним кодом не должны получить два ключа).
- **Защита от перебора**: не больше 5 неверных попыток на один выданный код — после этого код
  аннулируется, нужен новый. Счётчик попыток **не сбрасывается** запросом нового кода: дополнительно
  не больше 10 неверных попыток на адрес за час.
- **Лимит по IP** на неверные попытки (например, 20 в час на любые адреса).
- Код хранится в базе **хэшем** (например, HMAC-SHA256 с секретом сервера), сравнение — за постоянное время.
- Код — 6 цифр из криптостойкого генератора (`crypto.randomInt` / `secrets` и т. п.), не `Math.random`.
- Неверный код и истёкший код дают одинаковый ответ (`400`/`401`), без подсказки, что именно не так.

## Общее

- Все лимиты хранятся вне процесса (Redis/БД), чтобы не сбрасываться при перезапуске сервера и
  работать на нескольких экземплярах.
- IP берётся из заголовка доверенного прокси (`X-Forwarded-For` только от своего балансировщика),
  иначе лимит по IP обходится подменой заголовка.
- Журнал: запросы кодов и неудачные попытки (без самих кодов) — чтобы видеть атаки.
- Выданный ключ (`wa_…`) хранится на сервере хэшем, его можно отозвать; срок жизни — 30 дней.

## Как проверить

1. 6 запросов кода на один адрес подряд → начиная со второго — `429`.
2. 6 неверных кодов → шестой отклоняется даже с верным кодом; нужен новый код.
3. Верный код дважды → второй раз отказ.
4. Код через 11 минут → отказ.
5. Перезапуск сервера между шагами 1–2 не обнуляет счётчики.
