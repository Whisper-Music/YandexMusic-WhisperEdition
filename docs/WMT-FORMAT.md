# Whisper Music Theme (`.wmt`) — формат файла темы, версия 1

Один файл `.wmt` описывает тему оформления целиком: цвета, эффекты, шрифты, фон и CSS-правила
внешнего вида. Формат общий для всех приложений семейства Whisper: каждое приложение берёт общие
значения (`tokens`) и свою секцию CSS/настроек, а чужие секции пропускает.

Эталонная реализация разбора и сборки — `src/wmt.js` (без зависимостей, работает в браузере и в Node 18+).

---

## 0. Два вида файла (как темы Telegram Desktop)

**Текстовая тема** — файл `.wmt` с текстом (раздел 1). Цвета, шрифты, CSS. Фоновой картинки нет —
фон остаётся пустым, а тема всё равно применяется.

**Тема с фоном** — обычный zip-архив, переименованный в `.wmt`:

```
night-sky.wmt   (= zip)
├── theme.wmt        ← обязательно: текст темы (раздел 1)
├── background.jpg   ← фон; имя всегда background.<расширение>
├── preview.png      ← по желанию: картинка для карточки темы (manifest.preview)
└── myfont.woff2     ← по желанию: любые файлы, на которые ссылается тема
```

* Фон: `background.` + одно из `jpg jpeg png webp gif avif bmp` (картинка) или `mp4 webm m4v mov` (видео).
* Все файлы архива доступны теме по имени: `"asset:preview.png"` в JSON, `url(asset:myfont.woff2)` в CSS.
* Вид файла определяется по первым байтам: `PK\x03\x04` — архив, иначе текст. Расширение у обоих — `.wmt`
  (читатели также принимают тот же архив с расширением `.zip`).
* Архив можно собрать любым архиватором: «Сжать в zip» в Проводнике и т.п. Если файлы оказались внутри
  папки, читатель берёт папку, где лежит `theme.wmt`. Служебные `__MACOSX/` и `.DS_Store` пропускаются.
  Поддерживаются способы сжатия «без сжатия» (stored) и deflate; zip64 — нет.
* Править тему с фоном: переименовать `.wmt` → `.zip`, распаковать, поправить `theme.wmt`
  или заменить `background.*`, запаковать обратно и снова назвать `.wmt`.

Ограничения: файл темы — не больше 64 МБ, распакованные файлы — не больше 80 МБ вместе, видео-фон — не больше 48 МБ.

## 1. Устройство текста темы (`theme.wmt` или текстовый `.wmt`)

Текст в UTF-8. Его можно открыть и поправить в любом редакторе (VS Code, Notepad++…).

```
#WMT 1
# Строки с «#» до первой секции — комментарии для человека.

@@ manifest
{ … JSON … }

@@ tokens
{ … JSON … }

@@ settings whisper-music
{ … JSON … }

@@ css whisper-music
.panel { … }
```

* **Первая непустая строка** — `#WMT <версия>`, сейчас `#WMT 1`. Если число больше, чем знает
  приложение, файл не загружается («обнови приложение»). Допустимо `#WMT 1.2` — дробная часть
  означает совместимые дополнения и читателем версии 1 игнорируется.
* **Секция** начинается строкой `@@ <тип> [<имя>] [<кодировка>]` и длится до следующей строки,
  начинающейся с `@@`, или до конца файла. Пустые строки в конце секции отбрасываются.
  * `тип` — латиница в нижнем регистре, цифры, `-`, `_` (начинается с буквы).
  * `имя` и `кодировка` — без пробелов.
* Строка внутри секции не может начинаться с `@@` (иначе это будет новая секция).
* Перевод строки — `\n` или `\r\n`. Метка BOM в начале допускается и пропускается.
* Неизвестные типы секций читатель **обязан пропускать** без ошибки — так в формат можно добавлять
  новое, не ломая старые приложения.

### Секции

| Тип | Имя | Содержимое | Обязательна |
|---|---|---|---|
| `manifest` | — | JSON: кто и что | да, ровно одна |
| `tokens` | — | JSON: общие значения для всех приложений | нет, не больше одной |
| `css` | id приложения | CSS для этого приложения | нет |
| `settings` | id приложения | JSON: настройки этого приложения | нет |
| `asset` | имя файла | встроенный ресурс (устаревший способ) | нет |

**JSON-секции** (`manifest`, `tokens`, `settings`) — это JSON, в котором дополнительно разрешены
комментарии `// …` и `/* … */` и лишняя запятая перед `}` / `]` (как в настройках VS Code).

**Ресурсы.** Картинки, видео и шрифты кладутся **файлами в архив** (раздел 0). Тип определяется по
расширению: `png jpg jpeg gif webp avif bmp svg` — картинки, `mp4 m4v webm mov` — видео,
`woff2 woff ttf otf` — шрифты. Имя — `[A-Za-z0-9._-]`, до 100 символов.

Для совместимости читатели понимают и ресурс внутри текста — секцию `@@ asset <имя> base64`
(двоичные данные в base64, пробелы и переводы строк игнорируются) или `@@ asset <имя> text`.
Новые темы так не сохраняются: картинка в base64 раздувает текст и мешает его править.
Если в архиве есть файл с тем же именем, файл главнее секции.

## 2. `manifest`

```jsonc
{
  "id": "midnight-gold",          // обязательно: a–z, 0–9, «-», до 48 символов, начинается с буквы/цифры
  "name": "Полночное золото",      // обязательно: название для людей
  "author": "Вадим",              // необязательно, до 40 символов: показывается как «Автор · Название»
  "description": "Тёмное золото и синий акцент",
  "version": "1.0",               // версия самой темы (не формата)
  "base": "royal",                // встроенный стиль-основа (см. ниже)
  "apps": ["whisper-music"],      // для каких приложений есть секции (подсказка)
  "created": "2026-10-17T10:00:00Z",
  "preview": "asset:preview.png"  // необязательно: картинка для карточки темы
}
```

* `id` — постоянный идентификатор темы. **Повторная загрузка файла с тем же `id` обновляет тему**,
  с новым `id` — добавляет ещё одну. Совпадать с встроенными стилями нельзя.
* `author` — в Whisper Music показывается рядом с названием: «Вадим · Полночное золото» на карточке
  и строкой под списком стилей в компактном виде. Нет автора — только название. Автор встроенных стилей —
  Whisper Music (он же пишется в файл при «Сохранить стиль в файл» для копии встроенного стиля).
* `base` — на каком встроенном стиле основана тема. В Whisper Music: `neon`, `royal`, `steam`, `lolitta`.
  От основы тема наследует поведение, заданное кодом, а не CSS (например, у `lolitta` — банты и
  жемчуг на панелях и подбор контрастного текста). Неизвестное значение = `neon`.

## 3. `tokens` — общие значения для всех приложений

Это часть, которую понимает любое приложение семейства, даже если у него совсем другой интерфейс.
Все поля необязательны; приложение берёт то, что умеет применить.

```jsonc
{
  "color": {
    "accent": "#c9a24b",      // основной цвет (#rrggbb)
    "accent2": "#8b1e2d",     // второй цвет: кнопки, активные элементы (#rrggbb)
    "text": "#eadfc6",        // основной текст (любой цвет CSS)
    "muted": "#a39579",       // второстепенный текст
    "background": "#0e0b09"   // фон окна, когда нет фоновой картинки
  },
  "effects": {
    "glow": 6,                // свечение, px (0–48)
    "panelOpacity": 0.92,     // непрозрачность панелей (0.2–1)
    "dim": 0.1,               // затемнение фоновой картинки (0–0.85)
    "backgroundBlur": 6       // размытие фона, px
  },
  "font": {
    "body": "\"Palatino Linotype\", Georgia, serif",   // шрифт интерфейса (font-family)
    "display": "\"Cinzel\", Georgia, serif"            // шрифт заголовков
  }
}
```

Фоновая картинка в `tokens` не указывается: это всегда файл `background.*` в архиве (раздел 0).
(Старые текстовые темы могли ссылаться на фон через `"background": { "image": "asset:…" }` и секцию
`@@ asset` — читатели это понимают, но файл `background.*` в архиве главнее.)

Правила для читателей: цвета `accent`/`accent2` — строго `#rrggbb`; остальное — значения CSS без
`;`, `{`, `}`, `<`, `>`, `url(`; числа вне диапазона обрезаются по границам; неизвестные поля пропускаются.

Новые общие поля можно добавлять в следующих версиях — старые читатели их просто не заметят.

## 4. `css <приложение>` — внешний вид конкретного приложения

Обычный CSS. Пишется так, как будто тема — единственный стиль в приложении; привязку правил к теме
делает само приложение. В Whisper Music (`css whisper-music`):

* `.panel { … }` → действует как `:root[data-style="<id>"] .panel { … }`;
* `:root { … }` и `html { … }` → сам стиль: здесь задают переменные (`--text`, `--muted`, `--font-display`…);
* `:root[data-anim="off"] .x { … }` → `:root[data-style="<id>"][data-anim="off"] .x { … }`;
* `@media`, `@supports`, `@container`, `@layer` — правила внутри привязываются так же;
* `@keyframes` и `@font-face` — подключаются; имена, которые тема задаёт сама, приложение незаметно
  делает уникальными для темы (в CSS темы ими пользуются как обычно);
* `@property` не подключается: можно пользоваться только переменными, которые уже объявило приложение;
* `@import` не подключается (тема не может грузить внешние файлы).

Ресурсы из файла: `url(asset:font.woff2)`, `url("asset:pattern.png")`.

```css
@font-face { font-family: "MyFont"; src: url(asset:myfont.woff2) format("woff2"); }
:root { --font-display: "MyFont", serif; }
.side .nav { border-radius: 0; letter-spacing: .08em; }
```

Значения из `tokens` применяются **после** CSS темы, то есть главнее одноимённых переменных в CSS.

Всё, чего нет в теме, берётся из общего оформления приложения. Поэтому тема может быть и маленькой —
например, из одних `tokens` или пары правил.

Каждое приложение читает только свою секцию `css`. Другое приложение (например, `whisper-studio`)
кладёт рядом `@@ css whisper-studio` — один файл темы обслуживает оба.

### Id приложений

| Приложение | id |
|---|---|
| Whisper Music (этот плеер) | `whisper-music` |
| Виджет «Сейчас играет» для OBS (часть Whisper Music) | `whisper-obs` |

Новые приложения берут свой id в том же стиле (`whisper-<что-то>`).

## 5. `settings <приложение>` — настройки приложения

JSON, смысл которого знает только это приложение. В Whisper Music:

```jsonc
{
  "features": {           // что умеет тема — от этого зависит, какие настройки видит пользователь
    "glow": false,        // нет свечения: ползунок «Свечение» скрыт (по умолчанию есть только у основы neon)
    "panelOpacity": false,// панели всегда непрозрачные: ползунок «Прозрачность панелей» скрыт
    "animations": false   // нет анимаций: галочка «Анимации интерфейса» скрыта, анимации выключены
  },
  "colorOverrides": {     // «Тонкая настройка цветов»: ключ параметра -> #rrggbb или #rrggbbaa (с прозрачностью)
    "heading": "#f0e2b6",
    "mainBg": "#ffffff59"
  },
  "controls": { "volume": "knob" },  // громкость — ручка: #volBtn крутится перетаскиванием; громкость в CSS — var(--vol), 0…1
  "layout": "fixed",                 // режимы «Настройки → Расположение» не применяются, пока тема выбрана
  "buttons": {                       // свои кнопки: имя ([a-z][a-z0-9-]{0,23}) -> действие; до 16 штук
    "power": "wave"                  // в DOM: #thBtns > button.thbtn[data-th="power"], .on — действие включено
  },
  "console": {                       // интерфейс — командная строка вместо окна (или просто "console": true)
    "prompt": "user@whisper:~$",     // приглашение, до 40 символов
    "banner": "Привет!\nhelp — команды" // приветствие при запуске, до 1200 символов, \n — новая строка
  }
}
```

Как этим пользоваться в CSS (поворот ручки по `var(--vol)`, где ставить кнопки `#thBtns`, состояния `.on`) —
в гайде [THEMES.md](THEMES.md), раздел «Больше, чем CSS».

Действия `buttons`: `wave`, `play`, `next`, `prev`, `like`, `dislike`, `shuffle`, `repeat`, `mute`,
`vol-up`, `vol-down`, `full`, `sleep`, `more`, `page:wave`, `page:likes`, `page:stats`, `page:settings`,
`page:profile`. Неизвестные действия и имена пропускаются. Кнопка только нажимает соответствующую кнопку
приложения — тема не получает никаких других возможностей.

**Консоль (`console`).** Пока стиль выбран, обычный интерфейс скрыт, а вместо него — командная строка:
управление всем приложением командами (`help` — список). Сами команды — часть приложения: тема не может
добавить свои или выполнить код, она задаёт только приглашение, приветствие и вид. Текст консоли — основной
цвет стиля (`accent`), подсветка и приглашение — второй (`accent2`); фон стиля (картинка, видео, обложка)
виден под консолью, её непрозрачность — «Прозрачность панелей» (`effects.panelOpacity`).
Разметка для CSS темы: `#cli` (вся консоль), `.cli-out` (вывод), строки `.cl` с классами `.cmd` (введённая
команда), `.err`, `.dim`, `.ok`, `.hl`, `.hd` (заголовок группы), `.banner`; `.cli-status` (строка «что играет»),
`.cli-in` (строка ввода), `.cli-ps` (приглашение). Пример — `docs/examples/terminal.wmt`.
Выйти из консоли: команда `gui` (вернёт прошлый стиль) или Ctrl+Shift+Backspace.

Значения `colorOverrides` (и то, что пользователь задал в «Тонкой настройке цветов» поверх темы)
главнее CSS темы, включая правила с `!important`.

Поле в `features` не указано — берётся как у основы (`manifest.base`): свечение есть только у `neon`,
прозрачность панелей и анимации — у всех встроенных стилей.

## 5½. Виджет для OBS — `css whisper-obs` и `settings whisper-obs`

Whisper Music умеет показывать мини-плеер «Сейчас играет» на стриме: Настройки → «Виджет для OBS», затем в OBS
источник «Браузер» с адресом из настроек (`http://127.0.0.1:<порт>/`). Виджет — отдельная страница, и тема
может оформить её под свой стиль двумя необязательными секциями. Нет секций — виджет оформляется по основе
стиля (`manifest.base`) и его цветам. Старые версии приложения эти секции просто пропускают.

```
@@ settings whisper-obs
{
  "layout": "card",     // вид по умолчанию: "card" | "compact" | "bar" (пользователь может выбрать другой)
  "layouts": ["card", "compact"], // необязательно: какие виды стиль умеет. Остальные в настройках недоступны,
                                  // а выбранный раньше неподходящий вид заменяется на "layout" стиля
  "opacity": 0.55,      // непрозрачность фона карточки, 0…1 (пока пользователь не сдвинул ползунок)
  "size": [410, 270]    // необязательно: размер источника «Браузер» в OBS (ширина, высота; 40…4000) —
                        // показывается в подсказке в настройках вместо стандартного 520 × 130
}

@@ css whisper-obs
.w-bg { border-radius: 0; background: rgba(10, 10, 10, var(--alpha)); }
.w-title { letter-spacing: .04em; }
```

**CSS** пишется как обычно, без привязки к стилю — в виджете действует только CSS текущего стиля. Подключается
после встроенного оформления виджета, поэтому одинаковые правила темы главнее.

Разметка виджета:

```
#w.w                         [data-base] [data-layout] [data-playing] [data-empty] [data-paused-hidden]
├── .w-bg                    фон карточки (по умолчанию полупрозрачное «стекло»)
├── .w-art > img.w-cover     обложка
├── .w-info
│   ├── .w-title             название
│   ├── .w-artist            исполнители
│   ├── .w-bar > i           полоска прогресса
│   └── .w-time > .w-cur, .w-dur
├── .w-eq > i × 4            «эквалайзер», пляшет, пока играет
├── .w-play > i              значок «плей» на паузе / «пауза», пока играет (по умолчанию скрыт)
└── .w-deco > i × 6          пустые элементы для декора темы (по умолчанию скрыты)
```

* `.w-play` и `.w-deco` есть в разметке всегда, но спрятаны (`display: none`), чтобы не менять виджет у тем,
  которые о них не знают. Тема включает их сама: `.w-play { display: grid; … }`, `.w-deco { display: block; }`.
  Значок в `.w-play > i` уже нарисован (треугольник; при `data-playing` — две полосы) цветом `currentColor` —
  теме достаточно задать место, размер, цвет и фон кнопки. Это картинка, а не кнопка: виджет в OBS не нажимается.
* `.w-deco` — слой на всю карточку (`position: absolute; inset: 0`), каждое `i` внутри — `position: absolute`.
  Ручки, решётки, лампочки, антенны — что угодно; у каждого `i` есть ещё `::before` и `::after`.
  Состояние доступно через `#w[data-playing] .w-deco i:nth-child(…)` (например, горящая лампочка).
* Свободные псевдоэлементы для декора: `#w::before`, `#w::after`, `.w-bg::before`, `.w-bg::after`.
* Если тема полностью меняет раскладку, удобнее писать селекторы через `#w` (`#w .w-art { … }`):
  так они главнее встроенных правил видов вроде `.w[data-layout="compact"] .w-art`.

* `data-base` — основа стиля (`neon`, `royal`, `steam`, `lolitta`); `data-layout` — `card`, `compact` или `bar`.
* `data-playing` — трек играет; `data-empty` — ничего не играет (виджет спрятан);
  `data-paused-hidden` — пауза при включённом «Прятать на паузе» (виджет спрятан).
* Переменные на `#w`: `--a`, `--b` — основной и второй цвет (при динамическом фоне — цвета обложки),
  `--alpha` — непрозрачность фона (0…1), `--p` — доля прослушанного (0…1), `--cover` — `url()` обложки.
* `@keyframes`, `@media`, `@font-face` — можно. Ресурсы из архива темы — `url(asset:имя)`, они вставляются
  в CSS прямо в виджет (каждый не больше 1,5 МБ).
* Наружу виджет не ходит: `@import`, `url(http…)` и функции, принимающие адрес строкой (`image-set` и т. п.),
  вырезаются. Из сети загружается только обложка трека.

«Сохранить стиль в файл» кладёт в файл секции `whisper-obs` своего стиля как были, а у копии встроенного —
заготовку-подсказку.

Примеры: `docs/examples/terminal.wmt` — небольшая перекраска стандартной карточки;
`docs/examples/retro-tv.wmt` — виджет целиком в виде мини-телевизора (корпус 380 × 240, свой пиксельный
шрифт из архива, кнопка «плей» на экране, нарисованные ручки на `.w-deco`, виды `card` и `compact`).

Изменения виджета подхватываются, когда стиль загружен заново («Загрузить тему…» с тем же `manifest.id`):
приложение читает секции `whisper-obs` при загрузке темы и при запуске.

## 6. Как пользователь делает свою тему в Whisper Music

1. Настройки → «Стиль оформления» → выбрать стиль, который ближе всего к задумке.
2. «Сохранить стиль в файл…» — получится `.wmt` со всеми правилами этого стиля (уже без привязки к нему).
   Если у стиля стоит фоновая картинка или видео — это архив с `theme.wmt` и `background.*`, иначе просто текст.
3. Поправить текст темы: поменять `manifest.id` и `name`, цвета в `tokens`, правила в `@@ css whisper-music`.
   Для архива — переименовать в `.zip`, распаковать, поправить `theme.wmt` / заменить `background.*`,
   запаковать и снова назвать `.wmt`.
4. «Загрузить тему…» (или перетащить файл в окно) — в ряду стилей появится новый.
   Загрузка того же файла после правок обновляет стиль. Можно загрузить и один `theme.wmt` без архива —
   тема применится, фон будет пустым.

Если тема испортила вид окна: **Ctrl+Shift+Backspace** возвращает встроенный стиль.

## 7. Чтение в другом приложении (кратко)

```js
const WMT = require("./wmt.js");             // или <script src="wmt.js"> → window.WMT
const theme = await WMT.open(bytes);          // Uint8Array/ArrayBuffer файла: текст или архив — всё равно
                                              // (бросает WMT.WmtError с номером строки)
theme.archive;                                // true — тема пришла архивом
theme.manifest.name;                          // «Полночное золото»
theme.tokens.color?.accent;                   // «#c9a24b»
theme.css("whisper-studio");                  // CSS для своего приложения или null
theme.settings("whisper-studio");             // {} если секции нет
theme.background;                             // { name: "background.jpg", mime, bytes } или null — фона нет
theme.asset("asset:preview.png");             // любой файл архива по имени или null
```

Сборка: `await WMT.pack({ comment, manifest, tokens, css: { app: "…" }, settings: { app: {…} }, background: { ext: "jpg", bytes }, files: [{ name, bytes }] })`
— архив `.wmt`, а без фона и файлов — просто текст. Только текст: `WMT.serialize({ … })`.

Минимальная корректная тема:

```
#WMT 1
@@ manifest
{ "id": "tiny", "name": "Маленькая", "base": "neon" }
@@ tokens
{ "color": { "accent": "#3fb8af", "accent2": "#ff6f59" } }
```
